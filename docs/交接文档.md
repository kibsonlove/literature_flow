# 交接文档

> 用途：任何人/会话接手本项目前先读这一篇。更新于 2026-10-01（智能体化改造 P0–P2 已落地）。
> 代码结构详见《项目架构与开发指南.md》，改造方案详见《智能体化改造方案.md》，本文只讲"现状 + 决策 + 怎么接手"。

## 1. 项目一句话

通用文献管线工具（FastAPI 网页应用）：检索（OpenAlex/arXiv）→ 入库 Zotero → 批量精读生成笔记 → 知识库语义检索 → 维护工具箱。**已改造为智能体形态**：自然语言下指令 → LLM 出计划 → 确定性代码逐步执行 → 写库步骤挂起等用户确认。

## 3. 已拍板决策（不要重新讨论）

1. LLM 默认走**网页端 webchat**（零 API 费）；API 只作备选。两处通道由**侧栏「大脑」开关**统一控制（单篇精读 / 长文精读 / 智能体共用一处，双向同步）。
2. 编排用**粗粒度规划**：一次出计划 → 确定性执行 → 失败才回问 LLM（每任务上限 2 次）。不做逐步决策紧循环（webchat 每次开浏览器约 30 秒+）。
3. 首发**交互式面板**，自动化/定时放 P3。
4. 任务**只串行**（webchat 同一浏览器 profile），由 `app.py` 的 `_AGENT` 闸门保护。
5. 写库步骤必须人工确认，agent 无静默写权限。
6. 不用 LangGraph 等框架重构。
7. 前端保持**原生 HTML/CSS/JS、零构建**（用户拍板）。

## 4. 接手第一步

- 想继续开发：读方案第 2 节的 **P3**。
- 想先验收：在真机上跑一遍智能体完整链路。**必须用网页端通道测，别用 API（会花钱）**：
  1. `webapp/start.local.bat` 起服务（127.0.0.1:8000）；
  2. 侧栏「智能体」→ 输入一句**只读**任务（如"列出含 PDF 但还没有笔记的文献"）→ 生成计划 → 开始执行，看日志与总结；
  3. 再试一个含入库的任务，确认它在写库前停下来、并显示"将影响多少条"。

**测试红线**：只读任务可随便测；写库任务只用小样 + 当场同意可整删的测试分类，跑完清理并列清单。

## 6. 红线速查（违者返工）

- **改已有文件先说明方案征得同意**；删/合并先出清单。
- 指定文献必须走「从 Zotero 选择」`openZoteroPicker()`，禁止让用户粘贴 Zotero key。
- 方案选择必须用弹窗（AskUserQuestion）。
- 测试不拿用户真实文献端到端；写库测试用可整删的小样；**测智能体不要用 API 通道**。
- 自动分类只在现有分类树内匹配，绝不新建分类；归属是移动制。
- 指纹字符串 `"六维速览"`/`"六维精读"` 不能改（历史笔记识别用）。
- .bat 文件纯 ASCII + CRLF。
- 前端样式约定：按钮悬停 `filter: brightness(.93)` 不改背景色；`.muted` = `#6b6b6b`；`.danger` = `#c0392b`。
- **前端不得改动既有元素 ID**：`app.js` 用 `$("id")` 绑定了约 170 个 ID，重排布局时必须保留。
- Playwright **同步 API 不得进事件循环**：相关路由用 `def`，重活丢后台线程（`_agent_bg`）。
- **不要在整个任务执行期间持有任务锁**：一次执行可能几分钟，持锁会把前端轮询全部堵死（已踩过，见 `advance()` 的注释）。
- **中止必须"保留未执行的步骤"**：`abort()` 不许把 pending 标成 skipped（否则用户没法续跑——踩过）；真正的停止靠 `_ABORT_FLAG` 与后台线程协作，它在每轮循环开头问一次。
- **改了写库步骤的参数，上一次的「确认」必须作废**（`approved=False`、状态退回 `awaiting_confirm`）。否则"换了入库分类却沿用旧确认"，用户确认的其实是另一件事。
- **危险步骤的影响面不许缩水**：参数里带 `$sN` 引用而解析不到时，`_safe_impact()` 必须在文案里写明"实际影响面可能更大"，不能悄悄按空参数算成一个假数字。

## 7. 本机环境事实

- Python 解释器（唯一依赖齐全）：`C:\Users\PC\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。
- Zotero 10.0.3：程序 `D:\zotero\updated\zotero.exe`，数据 `D:\考古\论文`；**Zotero 常处于关闭状态**，本地 API 读接口会静默返回空——先查进程与 23119 端口再下结论（工具层已用 `_need_zotero()` 探活兜住）。
- 缓存/向量库在 `webapp/cache/`（可再生，kb.sqlite 重建成本高，勿随手删）；智能体任务在 `webapp/cache/agent_tasks/`（可再生，自动保留最近 40 个）。
- 本地 API 写授权凭据在 `webapp/config/paths.json`（gitignore，不入库）。

## 8. 未决事项

- P3（定时 / 无人值守）要不要做、何时做，由用户拍板；无人值守时 danger 步骤**不执行**，只攒成待确认清单。
- 精读已纳入 agent 可调度范围（`reading_candidates` + `batch_notes`），一次任务限一个批量精读。
- `docs/智能体化改造调研.md` 内容已全部并入《改造方案》，属可删的过时文件（**待用户确认后再删**）。
- `/api/settings` 会把 API key 明文回给前端用于回填输入框（原生既有行为，仅本机存取）——若要收敛需单独讨论。
- **PDF 抓取成功率偏低**（2026-10-01 实测 347 条）：301 条有 `oa_url`，实测 16 条样本中
  arxiv / aclanthology / ojs.aaai 的**直链全部成功**；`doi.org` 系列多为**落地页**（返回 HTML，被判"不是 PDF"）；
  `dl.acm.org` / `mdpi.com` / `academic.oup.com` 一律 **403**（出版商反爬：浏览器带 cookie/JS 能过，脚本裸 GET 不能）。
  另有 46/347 条压根没有 `oa_url`。这就是"我自己能打开、网页抓不到"的原因。
  可救回一部分的方向：把**落地页二级解析**（读 `<meta name="citation_pdf_url">` 或页内 `.pdf` 链接）并考虑 Playwright 兜底。
  注意 `download_pdf()` 已加**总时长上限**（`total_timeout`）——此前它只有单次 socket 超时，遇到慢速服务器会把整条任务拖死（踩过）。

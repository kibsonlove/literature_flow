# literature_flow

把 Zotero 变成你的 AI 文献助手：自动精读论文、把笔记写回 Zotero、再把全文建成能用大白话检索的知识库。

整套流水线跑在你自己电脑上（一个本地 Python 服务 + 你自己的 API key），不需要任何云端账号，文献数据始终留在本机。

---

## 一、它能做什么

| 功能 | 说明 |
|---|---|
| **单篇精读** | 挑一篇带 PDF 的文献，AI 按学科维度出一份结构化笔记，直接写进 Zotero |
| **批量精读** | 勾选一批文献，后台逐篇生成笔记，可随时停止 |
| **长文精读** | 学位论文 / 专著：先分章精读，最后自动汇总一份「全书总纲」 |
| **PDF 入库** | 把散落各处的 PDF 批量建成 Zotero 条目（自动补全 DOI 元数据） |
| **语义检索** | 全文切块做向量化，用自然语言提问，给出原文段落出处 |
| **文献订阅** | 按你给的期刊名单和关键词，从 OpenAlex 检索新发表文献 |
| **论文对比** | 把所有笔记的速览维度汇总成一张表，横向对照 |

笔记的维度不是写死的：程序会按文献内容自动匹配学科模板（「领域包」），匹配不上会让 AI 现造一个。你也可以在 `webapp/config/domains/` 里手动调整维度。

---

## 二、准备工作

- **Zotero 7** 已安装，且能正常打开（本程序通过它的**本地 API** 读写，不碰你的云端账号）
- **Python 3.10 或更高版本**
- 一个 **LLM 的 API key**（DeepSeek 或任意 openai 兼容服务都行）
- 可选：一个 **Embedding API key**，只做「语义检索」时需要。硅基流动的 `BAAI/bge-m3` 免费注册即可用

## 三、安装与启动

```bash
# 1) 装依赖（在 webapp 目录下）
cd webapp
python -m venv venv
venv\Scripts\pip install -r requirements.txt

# 2) 可选：想用「网页端」模式（走网页版大模型，零 API 费用）再执行这两条
venv\Scripts\playwright install chromium     # 下载浏览器内核，约 150MB
venv\Scripts\python login_deepseek.py        # 会弹出浏览器，登录一次即可，登录态会被保存

# 3) 启动（回到 webapp 目录后双击 start.bat，或直接执行下面这条）
venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

启动后浏览器会自动打开 `http://127.0.0.1:8000`。关闭程序：关掉那个黑色命令行窗口即可（不影响 Zotero）。

> 另有一个 `serve.bat`，只重启服务、不弹浏览器，日志写到 `webapp/logs/server.log`，适合后台跑。

## 四、配置：填什么、在哪里填

先进入 `webapp/config/`，把三个 `*.example.json` 各复制一份并去掉 `.example` 后缀，然后按下表填写：

| 配置文件 | 填什么 | 怎么填 |
|---|---|---|
| `settings.json` | LLM 的 `api_key` / `model` / `base_url` | **网页右上角「设置」按钮就能填**，也可以直接改文件 |
| `paths.json` | `zotero_data_dir`（Zotero 数据目录）、`zotero_exe`（程序路径） | **只能改文件**，界面没有入口 |
| `embedding.json` | 向量化服务的 `api_key` 等 | **只能改文件**，界面没有入口 |

补充说明：

- **Zotero 数据目录怎么找**：Zotero → 编辑 → 设置 → 高级 → 文件和文件夹 → 看「数据目录位置」，把那个路径（如 `D:/Zotero`）填进 `zotero_data_dir`。
- **Zotero 不需要填任何 key**。它只监听本机，程序零配置即可连上——只要 Zotero 开着就行。
- **MinerU 平台 key**：自己新建 `webapp/core/mineru_key.txt`，里面只放一行 key（mineru.net 注册即得）。
  - 不配也能正常**精读单篇文献**——只是会降级成纯文本处理，拿不到原文表格里的量化数据；
  - 但**「语义检索」和「长文精读」必须有它**：知识库是把 MinerU 的解析结果切块建索引的，没有解析缓存就没有东西可索引。
- 这三个 `.json` 都已写进 `.gitignore`，**永远不会被提交到仓库**。

## 五、怎么用

### 精读一篇文献

1. 点主页的 **「从 Zotero 选择」**，在弹出的选择器里搜索或翻分类树，挑一篇**带 PDF** 的文献（选中后输入框会显示标题，不需要你知道任何编号）
2. 选好后端（见下方说明），点 **「生成六维笔记」**
3. 等进度条走完，网页上会出现笔记预览，你可以直接编辑
4. 确认无误后点 **「确认回写 Zotero」**——笔记就挂到那篇文献下面了

### 两种后端可选

| 后端 | 费用 | 速度 | 说明 |
|---|---|---|---|
| **网页端 WebChat**（默认） | 免费 | 较慢 | 用你已登录的网页版大模型；**首次需先跑一次 `login_deepseek.py`** |
| **DeepSeek API** | 按量计费 | 快 | 需要 `settings.json` 里有可用的 key |

### 其他常用操作

- **手边只有 PDF、还没入库**：主页点「上传 PDF」→ 会自动建 Zotero 条目、挂附件、抽全文、出笔记，一条龙。也可以用顶栏 **「PDF 入库」** 批量囤文献，之后再走批量精读。
- **已有几十篇想一起读**：顶栏 **「批量笔记」** → 「读取候选」会自动列出"有 PDF 但还没有笔记"的文献 → 开始批量。列表会自动跳过已有笔记的条目，不会重复生成。
- **学位论文 / 专著**：点「长文精读」，上传 PDF 或从 Zotero 选。可以先填「限 N 章」小跑几章试试效果，再放开跑全书。
- **想按内容找文献**：顶栏 **「语义检索」** → 先点一次「更新索引」建库（需要用 MinerU 解析过）→ 之后就能用自然语言提问。
- **想知道该读哪些新文献**：顶栏 **「工具箱」** → 先编辑 `scripts/subscribe/lit_keywords.txt`（关键词）和 `lit_journals.txt`（重点期刊），再点「运行订阅」。参考 `scripts/subscribe/` 下的两个 `.example.txt` 模板。
- **横向对比读过的文献**：顶栏 **「论文对比」**，可筛选、可导出 CSV。

## 六、笔记和数据存在哪里

**重要：精读笔记不会落在本地文件里。**

它的归宿始终是 **Zotero**——网页上生成、你确认后，程序把它作为**子笔记**挂到对应文献条目下（如果那条文献原本不在库里，会自动新建条目）。所以你的知识沉淀只有一个地方：Zotero 库。换电脑时备份 Zotero 就够了。

本地会产生的其他东西：

| 位置 | 内容 | 能删吗 |
|---|---|---|
| `webapp/cache/` | 知识库向量库 `kb.sqlite`、MinerU 解析缓存 | 能删，删了重新建索引即可，不影响 Zotero |
| `reports/` | 工具箱生成的 HTML 报告、订阅候选清单 | 能删，重新跑工具会再生成 |
| `notes/material_pack.md` | 写作素材包，工具箱「重建写作素材包」的产物 | 能重建，但**别改文件名**——工具箱按固定路径读写它 |
| `webapp/logs/` | 服务运行日志 | 能删 |

## 七、目录结构

| 目录 | 内容 |
|---|---|
| `webapp/` | 主应用（FastAPI + 原生前端）。日常只需要动 `webapp/config/` |
| `webapp/config/` | 你的密钥、Zotero 路径、学科维度模板（全部不入库） |
| `webapp/cache/` | 运行数据：向量库与解析缓存（可再生） |
| `scripts/` | 独立脚本：`subscribe/` 订阅、`pipeline/` 笔记汇总、`dedup/` 去重、`tags/` 标签分析 |
| `reports/` `notes/` | 运行后生成的报告与素材包（不入库） |
| `docs/` | 《项目架构与上手指南》，含架构图与详细排错 |

## 八、关于哪些东西没随仓库分发

仓库只包含**通用代码与文档**。以下内容属于使用者个人的研究数据，需要你自己在本地生成或维护，**不会出现在仓库里**：

- `webapp/config/` 下的全部真实配置（密钥、路径）
- `notes/`、`reports/`、`archive/` 里的产物
- 订阅用的期刊名单与关键词（仓库只给 `.example.txt` 模板）
- 一部分带有个人研究预设的分析脚本。工具箱里若点到它们，会提示「脚本未找到……部分个人分析脚本默认不随仓库分发」，这是预期行为，不是故障

## 九、常见问题

| 现象 | 怎么办 |
|---|---|
| 浏览器提示"无法访问此网站" | 等 3～5 秒刷新；仍不行看命令行窗口的报错；重启 `start.bat`（它会自动清掉占用 8000 端口的旧进程） |
| 页面能开，但选文献时列表是空的 | Zotero 没打开。先启动 Zotero 再重试 |
| 点生成后报 key 无效 / 余额不足 | 去网页「设置」里更新 API key |
| 「语义检索」提示未配置 embedding | 填 `webapp/config/embedding.json` |
| 「语义检索」结果很少或为空 | 还没建索引，先点一次「更新索引」 |
| 网页端后端报错说找不到浏览器 | 执行过 `venv\Scripts\playwright install chromium` 了吗？另外要先跑一次 `login_deepseek.py` 登录 |
| 笔记的维度不像我这个学科 | 领域包没匹配上，回退到了通用维度。可在 `webapp/config/domains/` 里给对应学科补关键词 |
| 精读出来的数字对不上原文 | 该文献还没被 MinerU 解析过，表格数据没喂给模型。配置 `mineru_key.txt` 可改善 |

更多架构细节与排错见 **`docs/项目架构与上手指南.md`**。
